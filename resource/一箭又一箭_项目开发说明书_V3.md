# 一、作业要求缩略版

本次作业要求使用 **Python** 独立开发一个“一箭又一箭”风格的点击式箭头解谜小游戏，并至少使用一种 AIGC / Coding Agent 工具辅助开发。

## 1. 基础玩法

棋盘中存在若干方向为：

```text
上 / 下 / 左 / 右
```

的箭头。

玩家点击一个箭头后，需要判断它朝向的方向直到棋盘边界之间，是否存在其他箭头阻挡。

- 前方无阻挡：箭头飞出棋盘并消失；
- 前方有阻挡：箭头不能消失，并产生明显碰撞反馈；
- 点击被阻挡的箭头会消耗一次失误机会；
- 清空本关所有箭头后通关；
- 失误次数耗尽则本关失败；
- 玩家可以重新开始当前关卡。

课程基础版采用：

```text
单格箭头
+
同一行 / 同一列路径判断
```

不要求实现原商业游戏中的复杂折线箭头和机关。

# 二、我们的项目目标

本项目不会只停留在课程要求的“单格箭头基础版”。

总体目标是：

```text
先完整实现课程基础版
        ↓
再升级为多格箭头
        ↓
再加入折线箭头和路径交织
        ↓
做出接近原版的蛇形飞出效果
        ↓
最后增加求解、提示、评分等扩展能力
```

也就是说：

> 课程要求是项目的最低完成线，而不是最终目标。

# 四、核心架构原则

整个项目最重要的一条架构原则是：

> 从第一版开始，就把箭头设计成“路径”，而不是单独的一个格子。

统一数据思想：

```text
Arrow
=
一串连续的网格坐标
+
一个最终朝向
```

例如：

```text
单格箭头：
[(2, 3)]

直线箭头：
[(2, 1), (2, 2), (2, 3), (2, 4)]

折线箭头：
[(1, 1), (2, 1), (3, 1), (3, 2), (3, 3)]
```

这样：

```text
基础版
=
路径长度为 1 的 Arrow
```

后面升级成长箭头和折线箭头时不需要推翻整个系统。

# 八、V2 —— 多格箭头版

## 这个版本是什么

V2 开始突破课程基础规则。

一支箭头不再只是一个格子，而可以占据多个连续网格。

例如：

```text
────→
```

---

## 和 V1 的核心区别

V1：

```text
一个箭头 = 一个格子
```

V2：

```text
一个箭头 = 一条直线路径
```

因此：

> 阻挡关系开始从“箭头头之间的关系”升级为“箭头路径之间的关系”。

---

## V2 的核心目标

实现：

```text
多格直线箭头
路径占用
多格碰撞
多格飞出
```

---

## V2 必须实现的核心功能

### 1. 多格 Arrow

一支箭头可以拥有多个连续 cell。

例如：

```text
● ● ● →
```

这些格子全部属于同一个箭头。

---

### 2. 路径占用

系统需要知道：

```text
当前棋盘上每一个被占用的格子
属于哪一支箭头
```

形成统一的：

```text
occupied cells
```

---

### 3. 高级阻挡判断

点击箭头后：

```text
从箭头头部开始
沿 direction 向前检查
```

只要前进路线上存在其他箭头占据的格子：

```text
blocked
```

---

### 4. 多格飞出

箭头不能瞬间消失。

整条箭头需要向外运动并逐渐离开棋盘。

---

## V2 仍然不要求

这一阶段暂时仍然只做：

```text
直线箭头
```

不做：

```text
L 型
S 型
复杂折线
```

---

## V2 完成标准

至少能够实现：

```text
多个长直线箭头互相阻挡
点击正确箭头后整条路径离开
阻挡判断正确
基础关卡可以正常完成
```

---

# 九、V3 —— 原版玩法增强版

## 这个版本是什么

V3 是整个项目最重要的高级阶段。

目标：

> 从“课程作业小游戏”升级为真正接近原版“一箭又一箭”体验的游戏。

---

## 和 V2 的核心区别

V2：

```text
箭头只能是直线
```

V3：

```text
箭头可以是任意连续折线路径
```

例如：

```text
│
│
└────→
```

或者：

```text
┌───
│
└────→
```

多个折线箭头可以互相穿插、交织和阻挡。

---

## V3 的核心体验

棋盘看起来不再只是：

```text
↑ ↓ ← →
```

而应该逐渐接近：

```text
许多长短不同、弯曲不同的箭头
在网格上互相穿插
```

玩家需要观察：

```text
哪一支箭头现在可以出去
它移走后会释放哪一支箭头
整体消除顺序是什么
```

真正形成解谜感。

---

## V3 必须实现的核心功能

### 1. 折线箭头

一支 Arrow 可以包含：

```text
直线段
转角
多个转角
```

只要求路径连续。

---

### 2. 路径交织

不同箭头的形状需要形成明显的阻挡关系。

例如：

```text
A 阻挡 B
B 阻挡 C
C 移走以后 B 才能出去
B 移走以后 A 才能出去
```

---

### 3. 蛇形飞出动画

这是 V3 最重要的视觉升级。

折线箭头不能整体平移。

而应该像蛇一样：

```text
头部向前
后面的路径逐段跟随
尾部逐渐离开
```

最终整条折线被“抽”出棋盘。

---

### 4. 更真实的碰撞反馈

建议实现：

```text
箭头向前试探
碰到阻挡
变红 / 晃动
退回原位置
```

这样比简单闪一下更加接近原版体验。

---

### 5. 高级关卡

增加真正使用：

```text
长箭头
折线箭头
路径交织
```

的关卡。

推荐最终至少拥有：

```text
6~8 个完整关卡
```

难度逐步增加。

---

## V3 完成标准

玩家打开游戏后能够明显感受到：

> 这不是单格箭头作业的简单扩充，而是已经接近原版“一箭又一箭”的核心体验。

建议建立：

```text
v2.0-advanced
```

# 十一、V4 核心扩展功能

## 1. 提示系统

系统自动找到：

```text
当前可以安全飞出的箭头
```

高亮其中一个。

这是优先级最高的扩展功能。

---

## 2. Solver / 自动求解

使用：

```text
DFS
或
回溯
```

搜索完整通关顺序。

Solver 的作用不仅是给玩家自动解题，还可以：

```text
验证关卡是否有解
给提示
检测死局
辅助设计关卡
```

这是最有算法价值的扩展功能。

---

## 3. 自动演示

根据 Solver 给出的解法：

```text
自动依次执行正确步骤
```

让玩家观看整关如何解开。

---

## 4. 计时

记录每关完成时间。

用于：

```text
个人最佳成绩
星级评价
```

---

## 5. 星级 / 评分

可以根据：

```text
失误次数
提示次数
完成时间
```

进行简单评价。

例如：

```text
★★★
★★
★
```

---

## 6. 撤销

允许撤销上一步。

至少支持：

```text
恢复刚刚移除的箭头
恢复失误次数
```

---

## 7. 关卡选择

提供：

```text
Level Select
```

方便展示不同难度关卡。

---

## 8. 存档

使用 JSON 保存：

```text
已解锁关卡
最佳时间
星级
```

不需要数据库。

---

# 十七、Agent 开发时必须遵守的原则

## 1. 不要为了快速完成而把基础版写死

所有 Arrow 从一开始都应该使用统一的路径数据结构。

---

## 2. 基础版本必须始终可运行

开发高级功能时不能破坏：

```text
基本路径检测
失败机制
重新开始
关卡切换
```

---

## 3. 玩法逻辑和动画逻辑尽量分离

判断：

```text
能不能出去
```

和：

```text
怎么飞出去
```

应该是两个概念。

---

## 4. 关卡数据和游戏逻辑分离

不要把具体关卡硬编码进主逻辑。

---

## 5. Solver 不参与正常规则判定

正常游戏仍然根据实际棋盘状态判断。

Solver 只是：

```text
提示
验证
自动求解
```

工具。

---

## 6. 每次新增高级功能前先保证旧测试通过

避免：

```text
做出新动画
却把路径判断搞坏
```

---

# 十八、最终理想成果

最终项目希望形成这样一个完整作品：

```text
Python + Pygame
        ↓
完整满足课程要求
        ↓
支持单格箭头
        ↓
支持长直线箭头
        ↓
支持复杂折线箭头
        ↓
多个箭头可以互相交织阻挡
        ↓
箭头像蛇一样逐渐飞出棋盘
        ↓
拥有完整关卡难度曲线
        ↓
支持提示和自动求解
        ↓
拥有计时、评分、关卡选择等完整功能
```

最终项目的亮点应该集中在三件事：

```text
1. 基础功能完整且稳定
2. 对原版核心玩法进行了进一步还原
3. 使用 Solver 等算法增强关卡设计和游戏体验
```

而不是单纯堆叠大量无关功能。

---

# 十九、最终一句话定义

本项目不是：

> “做一个可以点击四个方向箭头的 Pygame 小作业”。

而是：

> **先以课程要求的单格箭头玩法作为可靠基础，再逐步扩展成支持长路径、折线交织、蛇形飞出和自动求解的完整箭头解谜游戏。**
