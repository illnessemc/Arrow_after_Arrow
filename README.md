# 一箭又一箭（折线生成版）

这是一个使用 Python 和 Pygame 开发的网格箭头解谜游戏。当前版本以“密集、
简洁、整条折线逐段抽出”为主要表现：箭头可以占据多个格子并多次转弯，
所有关卡都会铺满整块棋盘。

## 当前功能

- 开始、游戏、通关和失败页面；
- 多格直线箭头与多转角折线箭头；
- 点击箭头任意线段选择整支箭头；
- 箭头沿自身路径像蛇一样逐段前进并飞出棋盘；
- 受阻时向前试探、变红、晃动并扣除失误机会；
- 棋盘尺寸按关卡配置，界面会自动缩放；
- 深色纵向布局和确定性的多色箭头，相邻箭头不会同色；
- 背景、标题等外部图片使用可替换资源接口，缺省时回退到文字和图元；
- 1 个手工教学关和 4 个自动生成的正式关；
- 正式关同时包含大尺寸矩形和“凸”字形棋盘；
- 自动生成、完整覆盖检查和通关流程验证；
- 固定随机种子，同一版本的关卡可以稳定复现。

## 运行方法

建议使用 Python 3.10 或更高版本。

```bash
python -m pip install -r requirements.txt
python main.py
```

鼠标左键点击折线箭头，按 `Esc` 或关闭窗口退出。

## 核心设计

### 箭头和地图

`Arrow` 保存从尾部到头部的连续坐标序列，支持任意长度和多个直角转弯。
`GameBoard` 保存“格子 -> 箭头 ID”的占用索引，放入和移除箭头时会统一更新
全部身体格。点击线段任意位置都能找到整支箭头。

阻挡检测只需从箭头头部沿最终方向扫描。每个格子的占用查询为常数时间，
扫描成本与头部到棋盘边界的距离成正比；当前棋盘规模无需增加复杂空间索引。

### 动态棋盘

`BoardLayout` 独立描述棋盘行列数和可玩坐标，界面根据当前尺寸计算格子大小，
并未把玩法限定为固定的 7×9。生成规格可通过 `playable_cells` 使用缺角、
带空洞或多边形轮廓；当前最后一关使用上窄下宽的“凸”字形棋盘。

### 自动关卡生成

正式关采用在线、确定性生成：程序启动时根据 `GeneratedLevelSpec` 和固定种子
生成路径，无需逐支手写箭头。生成器先构造覆盖矩形全部格子的连续蛇形路径，
再用保持连续性和覆盖率的 backbite 变换将规则条带打散，最后切分为多支折线
箭头。部分边界切口会形成多个可释放入口，避免所有关卡都只有单一选择。

增加一关只需要追加规格：

```python
GeneratedLevelSpec(
    "新关卡",
    rows=12,
    cols=14,
    seed=20260925,
    min_arrow_length=6,
    max_arrow_length=16,
    boundary_break_chance=0.2,
)
```

`LevelGenerator` 是自动生成接口；以后可以并列增加模板拼接、文件读取或更复杂
的生成算法。生成结果仍是统一的 `Level`，不需要修改游戏主循环。

### 全覆盖和流程验证

每关默认使用 `CoverageMode.REQUIRE_FULL`。关卡创建时会检查越界、路径断裂、
格子重叠、重复 ID 和空格；因此每个可玩格必须恰好属于一支箭头。

`LevelSolver` 使用与正式游戏相同的规则尝试清空棋盘。当前基础规则具有单调性：
移除箭头只会减少阻挡，所以每步选择任意可飞出的箭头即可完成可靠验证；若某
一步没有可选箭头，关卡会在载入前被拒绝。求解报告还记录步骤数和每步可选数，
为后续关卡排序及难度曲线预留数据。

### 手工教学关

第 1 关“折线入门”保留为 7×9 手工关，显式路径便于讲解和调整。后续 4 关
分别为 12×16、14×18、16×20 和 18×18，均由生成器构造并由求解器验证；
最后一关只启用“凸”字轮廓内的 270 格。五关覆盖格数分别为 63、192、252、
320 和 270，全部可玩格无空位、无重叠。

### 规则扩展

`GameSession` 负责点击、失误次数和输赢状态；出界判断通过 `ExitRule` 注入，
当前仍使用基础的 `StraightExitRule`。以后增加特殊出口、转向、机关或新的
棋盘形状时，可以替换规则或生成器，而不用把逻辑堆进 Pygame 界面层。

### 界面资源扩展

`GameTheme` 集中保存界面颜色，箭头配色由邻接图自动分配，相邻箭头不会使用
同一种颜色。`AssetProvider` 为后续背景、标题和按钮素材保留按名称取图接口；
当前使用 `EmptyAssetProvider`，所以没有素材时仍能完整运行。

## 生成方式选择

本版本选择在线生成而不是保存离线关卡文件。当前算法只处理一个矩形路径、
局部路径变换和少量候选重试，固定关卡在启动时生成一次，成本远低于一帧；
固定种子也兼顾了可复现性。若以后加入全局搜索、复杂机关或高成本难度优化，
可以保持相同接口，把已验证的生成结果序列化为离线关卡。
